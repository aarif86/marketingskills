## What shipped this session

**Discovery (honest result)** — the session container had no Hostinger token, SSH key or connector, and egress to nsd.sg / hostinger.com / DNS was blocked. Documented in `docs/01-discovery-and-architecture.md` with a hPanel checklist for Aarif.

**Platform app** (`src/`) — Fastify 5 + better-sqlite3, ESM, six runtime deps.
- Host-header router: `nsd.sg`/`www` → platform, `*.nsd.sg` → tenant static server.
- Tenant server: extension→MIME allowlist, path re-validation + `lstat` (no symlinks), clean URLs, directory index, custom 404, security headers, GET/HEAD only, per-IP rate limit, traffic counters, 451 page for suspended sites.
- Badge injection at serve time (`src/serve/branding.js`): randomised id, `!important` inline styles, MutationObserver guard; removable via plan feature, per-user override, or per-site admin override.
- Storage engine: immutable release dirs, hard-link copy-on-write, rollback, plan-based pruning, unique-inode storage accounting. ZIP extraction rejects traversal/absolute names (yauzl refuses), symlinks, bombs (count/size caps + inflate guard), disallowed types; strips one wrapper folder; skips `__MACOSX`, `.DS_Store`, `node_modules`, `.git`, dotfiles.
- Auth: scrypt (N=2¹⁵), lockout after 8 failures, `__Host-` session cookie, CSRF (HMAC token + Origin check, also on multipart), rate limits, email verify + password reset via zero-dep SMTP client (logs to stdout if SMTP unset).
- Plans as data: `free` (90-day trial, 1 site, 100 MB, badge), `plus` (S$9, badge off, custom domains), `community` (private, NASAR HQ). Per-user JSON overrides. Extension and upgrade requests recorded as `plan_events`.
- Dashboard: sites list, create with live availability check, drag-and-drop ZIP / files / folders (client walks dropped directories, strips top folder), file manager (view inert / delete), versions + restore, settings (title, iframe opt-in), delete with name confirm, account (profile, password, sessions, self-delete), billing (usage, request extension, upgrade intent).
- Admin: overview (stats, extension + upgrade queues, security events), users (status, plan, extend, never-expire, overrides, notes, role, force-logout), sites (suspend, badge, rename, transfer, delete, reclaim = delete + reserve), plans editor, reserved names, abuse queue with one-click suspend, audit log, system health.
- Public: home, pricing, FAQ, terms, privacy, abuse report form, `/healthz`, Caddy `tls-ask` endpoint.

**Deploy kit** (`deploy/`) — Dockerfile (non-root), Compose (read-only rootfs, no caps, mem cap), Caddy image with Cloudflare DNS module, Caddyfile with `TLS_MODE=wildcard|ondemand`, `setup-vps.sh` (Docker, ufw, fail2ban, clone, .env, cron), `backup.sh` / `restore.sh`, `hostinger-dns.sh` (written from memory of the API; unverified), systemd unit alternative.

**Docs** — 01 discovery/architecture, 02 security model + launch checklist, 03 product spec, 04 Hostinger deployment, 05 business model, 06 operations. Plus `README.md`.

**Tests** — `npm test`: 31 passing (unit, hostile-ZIP fixtures built by a hand-rolled zip writer, end-to-end via Fastify inject covering cross-user isolation, badge toggling, suspension, abuse, deletion).

**Same-session bugs fixed**
- yauzl auto-closed the archive after the entry listing → `openReadStream` threw "closed". Cause: `autoClose` defaults true with `lazyEntries`. Fix: `autoClose: false`.
- Folder uploads lost their paths. Cause: busboy strips directories from `filename` unless `preservePath: true` is passed through `@fastify/multipart`. Fixed.
- yauzl's own traversal/size errors surfaced as 500s. Now wrapped as user-facing `ZipError` (whole archive rejected).
- `pkill -f "node src/server.js"` inside the same Bash call killed the shell (exit 144); use `setsid` for the background server and kill from a separate call.

## Decisions (and why)

- **VPS over shared hosting** — shared hosting cannot enforce the badge or the serving-layer allowlists and would run uploaded files through a shared LiteSpeed with PHP. Documented as unsupported.
- **SQLite over Postgres** — zero ops at this scale; data layer isolated for later.
- **Static-only tenants, no server-side execution** — removes whole attack classes; matches what AI tools produce.
- **Serve-time badge injection + ToS**, not upload-time rewriting — uploads stay pristine; enforcement can't be edited away; client-side JS removal is acknowledged as a policy problem.
- **No payment integration in MVP** — `/billing/upgrade` records intent; Stripe/HitPay slot documented.
- **Model E business model** (lead-gen for NasarDigital) with a small Plus tier; 3-month expiry is a conversation trigger, not a paywall.
- **Code lives in `marketingskills/nsd-sg/`** only because that repo was attached; README says to move it to its own repo.

## Quick reference

- **Run locally:** `cd nsd-sg && npm install && cp .env.example .env && npm run dev` → `http://localhost:3000`. Tenants need a Host header or `/etc/hosts` + `PLATFORM_HOSTS=nsd.sg,localhost`.
- **Tests:** `npm test` (in-memory DB, temp data dir).
- **CLI:** `node src/cli.js make-admin <email> [password] | set-plan <email> <plan> | plans | prune | stats`.
- **Prod deploy:** `docs/04-deployment-hostinger.md`. Secrets live only in `/opt/nsd/nsd-sg/.env` on the VPS (mode 600); never in the repo.
- **Gotchas that will bite on deploy:** `SESSION_SECRET` < 32 chars makes the app refuse to boot in production; production returns 421 for any Host not in `PLATFORM_HOSTS` (so a raw-IP check will “fail” by design); on-demand TLS needs `TLS_ASK_TOKEN` to match between `.env` and Caddy (Compose passes the same `.env` to both); Caddy `max_size` (120 MB) must stay above `MAX_UPLOAD_BYTES`.
